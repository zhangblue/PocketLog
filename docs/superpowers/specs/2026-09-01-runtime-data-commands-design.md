# 运行时数据命令设计

## 目标

将数据库迁移、演示数据写入、服务启动和账本清理拆分为职责清晰的显式命令，避免服务启动时写入账本数据。

## 命令语义

- `migrate`：连接数据库并执行 schema 迁移；只创建或升级结构，不写入分类、账户、交易或其他演示数据。
- `demo`：先校验 schema，再仅在空账本中写入内置演示分类、账户和交易。账本已有任何业务数据或已完成演示初始化时不覆盖、不重复写入。
- `serve`：只校验 schema、校验前端静态资源并启动 HTTP 服务；不得写入演示数据或其他账本数据。
- `clean`：先校验 schema，再在一个事务中清空账本业务数据，并将演示初始化门闩重置为未初始化状态；不删除表、不执行 migration。此后只有显式执行 `demo` 才会重新写入演示数据。

## 数据边界

`clean` 清除交易、分类、账户、自定义图标、幂等请求和与账本内容相关的状态；保留 schema 与 `app_state` 单例行，并重置其 seed/data revision 状态。清理需使用事务，任一步失败必须回滚，不能留下部分清空状态。

## 测试

- `migrate` 后所有业务表为空。
- 空账本执行 `demo` 后写入演示数据；重复执行不重复写入；非空账本不覆盖用户数据。
- `serve` 不再触发演示数据写入。
- `clean` 清空所有业务数据、重置门闩，并允许后续 `demo` 正常重新填充。
- 命令解析、使用说明和运行时配置加载覆盖 `demo`、`clean`。
