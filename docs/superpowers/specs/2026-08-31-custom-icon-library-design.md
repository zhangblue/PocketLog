# 共享自定义图标库设计

## 目标

在分类管理页面中，将自定义图标从分类创建/编辑表单中独立出来。用户添加的 Emoji 持久化到数据库，并在支出、收入分类共用的固定图标下拉框中可选。

## 交互

- 分类管理页增加独立的“自定义图标”区域，包含 Emoji 输入框、添加按钮和已保存图标列表。
- 分类新增和既有分类编辑只保留图标下拉框，不再显示自由输入 Emoji 输入框。
- 下拉框由内置固定图标与自定义图标合并组成，选项只显示 Emoji；支出和收入使用同一列表。
- 添加成功后立即刷新图标库和分类表单选项；添加失败保留输入内容并显示可恢复错误。
- 空白、超过 16 个 Unicode 字符或重复 Emoji 不得保存，并显示用户可理解的错误提示。
- 已被分类使用的自定义图标仍可继续展示；本次不提供图标删除，避免破坏历史分类展示。

## 后端与持久化

- 新增 `custom_icons` 表，至少包含 `id`、规范化后的 `emoji`、`created_at`；Emoji 唯一约束与 1–16 Unicode 字符业务校验。
- 通过显式 `migrate` 命令创建表；`serve` 只校验 schema，绝不自动迁移。
- Bootstrap 或独立图标接口返回共享自定义图标列表和当前 `dataRevision`。
- 新增 `POST /api/v1/custom-icons`，请求 `{ emoji }`；服务层在写事务中校验输入、检查重复、插入图标并递增 revision。
- 分类列表/Bootstrap 将自定义图标一并返回，前端首次加载即可构建下拉选项。
- 数据库唯一冲突、校验失败和 revision 冲突映射为稳定的业务错误；任何失败不得更新前端图标库或分类状态。

## 前端状态

- FinanceProvider 在 bootstrap 状态中维护 `customIcons`，并暴露 `createCustomIcon(emoji)` 动作。
- 成功响应以服务端返回的规范化 Emoji 和 revision 更新状态；失败时保留输入，不乐观添加。
- 分类创建/更新请求只发送所选 Emoji，不再发送自由输入字段。
- 若历史分类 Emoji 不在固定或自定义列表中，编辑下拉框临时保留当前值，避免编辑时丢失历史数据。

## 无障碍与样式

- 图标输入、添加按钮和下拉框提供清晰的 `aria-label`。
- 添加按钮不折行；图标下拉保持约 44px 紧凑宽度。
- 添加成功/失败使用现有可访问反馈机制；输入错误时焦点回到 Emoji 输入框。

## 测试

- 后端领域/服务测试覆盖有效 Emoji、空白/超长/重复错误、revision 和事务回滚；API 测试覆盖创建图标与 Bootstrap 返回。
- 前端 Provider 测试覆盖成功追加、失败不污染状态及分类请求只发送选择值。
- 页面测试覆盖独立添加区域、添加成功出现在分类下拉、空输入错误和固定/自定义图标合并展示。
- 执行 PostgreSQL 集成测试、前端全量测试、TypeScript 检查和生产构建。

## 范围外

- 不实现自定义图标删除、排序、上传图片或按分类类型隔离。
- 不改变分类生命周期、交易数据和统计逻辑。
