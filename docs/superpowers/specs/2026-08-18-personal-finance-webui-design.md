# 栖账：个人记账软件 Web UI 设计规格

- 日期：2026-08-18
- 状态：设计评审通过，等待书面规格复核
- 产品形态：面向 1024 px 及以上屏幕的桌面端 Web 应用
- 首版方向：个人日常收支、消费洞察优先

## 1. 产品定义

栖账是一款面向个人用户的日常记账 Web 应用。首版的核心价值不是监督预算，而是帮助用户快速理解“钱花到了哪里、相比过去发生了什么变化、哪些具体交易形成了这些变化”。

产品以月度财务总览为入口，形成“记录一笔 → 观察趋势 → 理解原因 → 回顾整月”的闭环。桌面端是主要使用场景，强调信息密度、图表可读性和多维分析效率。

### 1.1 目标用户

- 有稳定日常收支，希望持续记录个人消费的用户。
- 已经在记账，但难以从流水中获得有效结论的用户。
- 更重视消费趋势和生活规律，而非专业会计或企业财务能力的用户。

### 1.2 首版成功标准

- 用户在首页 10 秒内识别本月支出、最大支出分类和主要变化。
- 用户可在任意主页面 3 个操作步骤内完成一笔支出记录。
- 每条自动洞察都能下钻到支撑结论的交易明细。
- 月度报告能用简洁语言解释本月最重要的消费变化，而不是重复堆叠图表。

### 1.3 首版范围

首版包含：

- 财务总览
- 收支明细
- 快捷记账
- 分类管理
- 支付账户标签管理
- 支出、收入和账户间转账记录
- 消费趋势与分类分析
- 自动消费洞察
- 月度报告与 PDF 导出入口

首版不包含：

- 分类预算、超支提醒和储蓄目标
- 资产负债管理
- 订阅管理
- 多人或家庭共享账本
- 银行卡、支付平台自动同步
- CSV 或其他外部账单导入
- 多币种换算

## 2. 设计原则

### 2.1 洞察先于流水

首页先展示结论，再提供趋势、构成和明细。交易列表用于解释洞察，不作为首屏的唯一主体。

### 2.2 克制而可信

采用“静谧账本”视觉方向：米白背景、墨绿色主色、低饱和辅助色。视觉应有生活质感，但不能削弱财务数据的精确感。

### 2.3 所有结论都可追溯

分类占比、趋势变化和自然语言洞察均可点击。点击后进入已经带好筛选条件的交易明细，并在返回时恢复原来的时间范围和滚动位置。

### 2.4 异常可恢复

错误只影响发生问题的局部区域。保存失败时保留全部输入；删除单笔交易后提供撤销；不可恢复的批量操作必须二次确认。

## 3. 信息架构

桌面端使用固定左侧导航，包含以下一级入口：

1. 总览
2. 收支明细
3. 消费分析
4. 月度报告
5. 分类管理

左侧导航底部展示当前用户和“个人账本”身份。全局右上角始终提供“记一笔”按钮，打开快捷记账侧滑层，不切换当前页面。

### 3.1 总览页层次

首页从上到下按以下顺序组织：

1. 月份选择与快捷记账
2. 本月支出、本月收入、结余率、日均支出四项指标
3. 支出趋势与分类构成
4. 三条本月重点洞察
5. 最近交易明细

信息层次必须遵循“全貌 → 原因 → 证据”，避免在指标卡和图表中重复同一信息。

## 4. 核心页面

### 4.1 总览

总览默认展示当前自然月。主指标“本月支出”使用墨绿色反白卡片，其他指标使用浅色卡片。每个指标同时提供绝对值和具有上下文的比较说明，例如“较上月减少 8.4%”。

支出趋势以本月为主线，可叠加上月作为弱化对照。分类构成显示前四大分类与“其他”。洞察区最多展示三条重要结论，优先级依次为异常变化、显著改善和稳定表现。

### 4.2 收支明细

明细页提供时间、收支类型、分类和账户筛选。列表字段包括交易名称、分类、账户、日期、备注摘要和金额。

用户从分析页下钻进入时，页面显示当前筛选来源，例如“来自洞察：周末交通支出偏高”。清除筛选后返回完整明细。

### 4.3 快捷记账

快捷记账以侧滑层或居中浮层覆盖当前页面。字段顺序为：

1. 类型：支出、收入、转账
2. 金额
3. 常用分类
4. 账户
5. 日期与时间
6. 备注

默认选中“支出”，金额输入自动聚焦，常用分类按个人近期使用频率排序。保存成功后关闭浮层、展示成功反馈，并刷新当前页面受影响的数据。用户选择“保存并继续”时清空金额和备注，保留上一笔的类型与日期。

账户在首版中只是交易来源标签，例如现金、微信支付、支付宝和银行卡；不计算账户余额，也不形成资产视图。账户间转账不计入收入或支出汇总。

### 4.4 消费分析

分析页支持本月、近 3 个月和自定义时间范围，并允许按账户筛选。核心内容包括：

- 支出趋势
- 分类占比
- 与上一周期的分类对比
- 自动洞察

图表的日期点、柱形和分类扇区均可交互。交互后显示对应金额、占比和变化值，并允许进入明细页查看具体交易。

### 4.5 月度报告

月度报告由四部分组成：

1. 一句话月度总结
2. 财务状态评分与变化说明
3. “省得最多”和“增长最多”两项亮点
4. 自然语言消费故事

报告语气客观、温和，不使用羞辱性或制造焦虑的措辞。导出入口明确标注 PDF；导出内容与页面信息保持一致。

### 4.6 分类管理

分类管理允许查看、创建、重命名、排序和停用分类。已经被交易使用的分类不能直接永久删除，只能停用或将其交易迁移到其他分类后删除。

同一页面提供“账户标签”次级页签，用于管理记账时使用的支付来源标签。这里不展示账户余额、资产变化或对账能力。

## 5. 组件职责

### 5.1 应用框架

负责一级导航、用户身份、全局月份上下文和快捷记账入口。页面内容不自行复制全局导航状态。

### 5.2 指标卡

负责展示一个指标的名称、数值和比较说明。组件只接收已经计算完成的展示数据，不自行推断趋势。

### 5.3 图表面板

负责标题、时间说明、图例、图表和下钻动作。所有图表都必须有可被辅助技术读取的文字摘要，并提供不依赖颜色的图例。

### 5.4 洞察卡

负责展示结论、简短原因和下钻入口。每条洞察必须绑定明确的筛选条件，不能出现无法验证的泛化结论。

### 5.5 交易列表

负责展示经过筛选的交易集合、筛选来源和空结果状态。编辑、删除和撤销动作均在该组件范围内反馈。

### 5.6 快捷记账层

负责收集并校验一笔交易。关闭前若有未保存输入，应提示用户继续编辑或放弃；保存失败时不得清空字段。

## 6. 数据与界面流转

### 6.1 新增交易

1. 用户在任意主页面点击“记一笔”。
2. 快捷记账层收集类型、金额、分类、账户、时间和备注。
3. 提交成功后，新交易加入明细集合。
4. 当前月份的指标、趋势、分类构成和洞察使用新数据刷新。
5. 页面显示成功反馈，并保留用户原来的页面位置和筛选状态。

### 6.2 洞察下钻

1. 用户点击一条洞察。
2. 系统读取洞察绑定的时间、分类、账户或交易类型条件。
3. 进入明细页并显示筛选来源。
4. 用户可继续收紧条件或清除筛选。
5. 返回分析页时恢复先前视图。

### 6.3 月度报告

1. 用户选择一个已经结束或正在进行的月份。
2. 报告读取该月指标、分类变化和代表性交易。
3. 页面生成固定结构的总结、评分、亮点和消费故事。
4. 用户可下钻到明细或导出 PDF。

## 7. 数据展示规则

- 默认货币为人民币，使用 `¥` 和千位分隔符；金额保留两位小数仅在录入或确有小数时显示。
- 支出显示负号，收入显示正号；颜色只作为辅助，不作为唯一判断依据。
- 账户间转账不计入收入、支出、结余率或消费趋势，只在明细中记录资金来源与去向标签。
- 百分比同时显示方向和比较周期，例如“较上月减少 8.4%”。
- 时间范围始终可见，避免用户误把部分月份数据当作整月数据。
- 无足够历史数据时不生成趋势结论，改为说明“积累更多记录后可查看对比”。
- 自动洞察最多同时展示三条，且不得重复图表标题已经表达的事实。

## 8. 状态与错误处理

### 8.1 加载

页面首次加载使用与真实布局一致的骨架屏。耗时不足 300 毫秒的刷新不显示骨架，避免闪烁。局部图表刷新只替换该面板，不遮挡整页。

### 8.2 空状态

- 首次使用：解释记下第一笔交易后可以获得什么，并提供“记第一笔”按钮。
- 筛选无结果：显示当前筛选条件，提供“清除筛选”动作。
- 历史不足：保留已有数据，明确说明尚不能形成趋势结论。

### 8.3 保存失败

保留金额、分类、账户、时间和备注。错误信息说明数据没有丢失，并提供重新保存。网络恢复后不自动重复提交，避免产生重复交易。

### 8.4 删除

删除单笔交易后立即从列表隐藏，并显示带“撤销”的反馈条。撤销期结束后完成删除。清空账本等不可恢复操作必须显示影响范围并要求二次确认。

### 8.5 面板失败

单个图表或洞察加载失败时只显示该面板的错误状态和重试按钮，其他指标与明细保持可用。

## 9. 视觉规范

- 背景：柔和米白，降低长时间查看图表的疲劳。
- 主色：墨绿色，用于导航、主指标、主要按钮和选中状态。
- 辅助色：低饱和薄荷绿、陶土橙和沙色，用于图表分类。
- 卡片：浅色实体卡片配细边框，阴影克制，仅用于浮层和关键悬浮状态。
- 圆角：卡片 14–16 px，按钮与输入框 8–10 px。
- 字体：中文优先使用系统无衬线字体；金额和关键指标使用较高字重。
- 图表：避免超过五种同时出现的分类色；其余数据归入“其他”。

## 10. 响应式与无障碍

- 基准画布为 1440 px 宽桌面页面。
- 1280 px 及以上展示完整侧栏。
- 1024–1279 px 收起侧栏文字，仅保留图标和可访问名称；核心图表不降级。
- 首版保证 1024 px 及以上桌面体验，不把手机端完整交互作为验收范围。
- 键盘可完成一级导航、筛选、快捷记账、保存和关闭浮层。
- 焦点样式始终可见；浮层打开后焦点限制在浮层内，关闭后返回触发按钮。
- 正文和关键控件达到 WCAG AA 对比度。
- 趋势不能只用红绿区分，必须辅以箭头、数值和文字。
- 尊重系统的减少动效设置。

## 11. 验收场景

### 11.1 正常路径

- 从总览打开快捷记账，完成一笔支出，首页指标与最近明细正确刷新。
- 点击分类构成中的“餐饮”，进入带“餐饮 + 当前月份”筛选的明细页。
- 点击“周末交通支出偏高”洞察，看到形成该结论的交易集合。
- 切换月份后，总览、分析和月度报告使用同一月份上下文。
- 导出的月度报告与页面中的核心数据和结论一致。

### 11.2 边界与异常

- 没有交易时展示首次使用引导，不显示无意义的零值图表。
- 自定义筛选无结果时展示筛选摘要和清除动作。
- 保存交易失败时，所有输入保持不变，重试不会产生重复交易。
- 单个图表加载失败时，其余页面内容仍可操作。
- 删除交易后可在反馈条消失前撤销。
- 历史数据不足一个完整比较周期时，不显示未经支持的环比结论。

### 11.3 可访问性

- 仅使用键盘可完成一笔交易记录。
- 屏幕阅读器能获得图表的标题、时间范围、关键数值和文字摘要。
- 关闭浮层后焦点返回“记一笔”按钮。
- 开启减少动效后，图表和浮层不播放非必要动画。

## 12. 设计交付边界

本规格只定义首版 Web UI 的产品范围、页面结构、交互行为、视觉方向和验收标准，不包含技术选型、后端接口、数据库结构或实现代码。后续实现计划应以本规格为唯一设计基线，任何新增功能先经过范围确认。
