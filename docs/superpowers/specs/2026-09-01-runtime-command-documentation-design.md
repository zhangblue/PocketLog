# 运行时命令文档同步设计

## 目标

让项目约束文档和用户使用文档准确描述当前运行时命令的职责、数据边界与部署顺序，避免将 `demo` 误用为建表或预置分类初始化命令。

## 范围

仅修改 `AGENTS.md` 和 `README.md` 中与运行时数据命令有关的说明；不修改 Rust 代码、数据库 schema、配置模板、测试或发行包。

## 命令模型

| 命令 | 职责 | 是否写入业务数据 |
| --- | --- | --- |
| `migrate` | 显式创建或更新数据库 schema | 否 |
| `init` | 按名称幂等补齐十一项预置分类 | 是，仅分类 |
| `demo` | 在已初始化分类的空账本中写入演示账户和交易 | 是，仅演示账户与交易 |
| `clean` | 清空全部账本业务数据，保留 schema 和迁移记录 | 是，删除业务数据 |
| `serve` | 校验 schema、准备静态资源并启动 HTTP 服务 | 否 |
| `package` | 构建并组装发行目录 | 否 |

首次部署或清空后重建演示账本的命令顺序为 `migrate → init → demo → serve`；已有 schema 时不重复执行 `migrate`。

## 文档变更

### AGENTS.md

在“技术与数据”中补充数据生命周期约束：`init` 是预置分类初始化命令，`demo` 不创建分类且要求已完成 `init`，`clean` 后若需要演示数据必须执行 `init → demo`。同时列出支出“餐饮、交通、购物、居住、娱乐、通讯、网络、水费、电费”和收入“工资、其他”十一项预置分类。

### README.md

保留现有本地开发、打包和部署章节。将运行时命令说明统一为同一语义，并在首次部署与清空后的说明中明确 `init → demo` 的顺序及 `demo` 的空账本限制。

## 验收

- 两个文档对六个命令的职责与是否写入数据描述一致。
- 两个文档均说明 `serve` 不自动迁移或写入数据。
- 两个文档均说明 `demo` 不创建预置分类，且需要先执行 `init`。
- 两个文档均列出十一项预置分类或引用其完整清单。
- 文档中的命令顺序不出现 `clean → demo` 的旧流程。
