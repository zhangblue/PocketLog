# 栖账 / PocketLog 设计规格编年汇总

本文件按原始规格的日期与文件名汇总 `docs/superpowers/specs/` 中的设计决策，供维护者快速了解产品、后端、发行包、图表与分类管理功能的演进。原始规格全部保留；本文件只提炼目标、关键决策、边界和验收重点。

> 当前运行时数据命令以 [2026-09-01 运行时命令文档同步设计](./2026-09-01-runtime-command-documentation-design.md) 为准。较早文档中「`serve` 自动写入演示数据」和「`demo` 创建预置分类」的描述仅代表当时设计，已被后续命令模型取代。

## 2026-08-18：个人记账 Web UI 基线

原文：[个人记账软件 Web UI 设计规格](./2026-08-18-personal-finance-webui-design.md)

- **产品定位：** 栖账是面向个人用户的桌面端记账应用，核心闭环为“记录一笔 → 观察趋势 → 理解原因 → 回顾整月”。首版面向宽度不低于 1024 px 的屏幕，强调消费洞察而非预算监督或专业会计。
- **范围：** 包含总览、收支明细、快捷记账、分类与账户标签、收入/支出/转账、消费分析、自动洞察、月度报告和 PDF 导出入口；不包含预算、资产、订阅、导入、多币种、同步或多人能力。
- **信息架构：** 一级页面为总览、收支明细、消费分析、月度报告和分类管理；全局提供月份上下文与“记一笔”入口。总览遵循“全貌 → 原因 → 证据”，展示指标、趋势、分类构成、洞察和最近交易。
- **核心交互：** 快捷记账支持三种交易类型，转账不计入收支；洞察必须下钻到带筛选条件的明细并能恢复原视图；月报由汇总、评分、亮点和消费故事构成。
- **体验原则：** 使用“静谧账本”视觉（米白、墨绿、低饱和辅助色）；所有结论可追溯；局部错误可恢复；删除提供撤销，批量不可逆操作必须二次确认。
- **无障碍与验收：** 关键操作可键盘完成，图表提供文字摘要，浮层有焦点管理，金额使用人民币格式；空态、历史不足、保存失败、图表失败和删除撤销均有明确验收路径。

## 2026-08-26：Rust 后端基线

原文：[Rust 后端设计规格](./2026-08-26-rust-backend-design.md)

- **技术与架构：** 后端位于 `backend/`，采用 Rust、Axum、SeaORM 和 PostgreSQL 的分层模块化单体。Axum 同时提供 `/api/v1` JSON API 与前端静态资源，PostgreSQL 是财务数据的唯一事实来源。
- **数据模型：** 分类、账户标签、交易、`app_state` 和幂等请求均由数据库约束保证；金额使用 `NUMERIC(18,2)` 与十进制定点值；用户本地日期、时间、UTC 偏移独立保存，月份和周末判断不依赖宿主时区。
- **写入一致性：** 交易创建使用幂等键与数据修订号；标签操作、分类迁移、删除和恢复都在事务中执行。删除有固定 5 秒撤销窗口，后台物理清理不改变可见业务修订号。
- **查询规则：** 总览、分析与月报使用只读一致性快照；支出构成采用前四类加“其他”；趋势补齐零值日期；周末交通、分类环比、结余率洞察和月报评分均由固定、可测试的规则生成。
- **API 与错误契约：** 使用 `/api/v1`、`camelCase` JSON、`If-Match` 修订控制及 `application/problem+json` 错误响应。前端只在服务端写入成功后更新状态，失败保留草稿或原有界面状态。
- **运行与质量：** `migrate` 是唯一 schema 变更入口，`serve` 不自动迁移；包括静态资源回退、健康检查、结构化日志、优雅停机、真实 PostgreSQL 集成测试与前端跨页面测试。
- **历史说明：** 原规格曾规定 `serve` 在首次运行时写入演示数据；该部分已被 2026-09-01 的显式 `init` / `demo` 命令模型取代。

## 2026-08-28：独立发行包

原文：[独立发行包设计](./2026-08-28-standalone-release-design.md)

- **交付形态：** `package` 生成 `release/PocketLog-<target>/`，包含 `pocket-log-backend`、同级 `config.toml`、`dist/` 和 `logs/`。直接运行可执行文件等价于 `serve`，由同一进程托管前端和 API。
- **路径与配置：** 运行时路径相对可执行文件解析，改变当前 shell 目录不影响配置、静态资源或日志。若同级 `config.toml` 存在则必须读取并校验它；仅缺失时才回退到开发环境变量。
- **启动边界：** `serve` 在绑定端口前校验配置、`dist/index.html`、数据库连接与 schema，任一失败即非零退出，绝不自动迁移。`package` 仅构建和复制产物，不连接数据库或启动服务。
- **日志：** 使用按日滚动的 JSONL 文件 `logs/PocketLog-YYYY-MM-DD.jsonl`，同时保留紧凑控制台日志；按 `retention_days` 清理已过期的匹配日志，未知文件不删除。
- **验收：** 覆盖路径解析、配置脱敏、日志保留、发行目录启动、静态资源/配置/schema 失败以及重复打包不覆盖已有 `config.toml`。

## 2026-08-29：消费分析柱状图

原文：[消费分析柱状图坐标与提示设计](./2026-08-29-analytics-bar-chart-interaction-design.md)

- 横轴日期不超过 6 个标签；数据较多时均匀抽样文字并保留首尾，所有柱子仍完整绘制。
- 纵轴根据最大金额生成从 `¥0` 开始的 4 个等距刻度；金额与日期格式复用现有规则。
- 鼠标悬停或键盘聚焦柱子显示完整日期和精确金额；Enter 或 Space 可进入该日明细。
- 移除柱状图下方重复的逐日日期按钮列表；图表仍保留标题、描述和完整文字摘要。
- 修改范围仅限前端趋势图、样式与测试，不改变 API、统计口径或下钻语义。

## 2026-08-30：分类固定图标选择器

原文：[分类固定图标选择器设计](./2026-08-30-category-icon-picker-design.md)

- 为新增分类提供固定 Emoji 图标选择，默认 `🏷️`，并定义支出与收入常用图标集合；支出集合包含通讯、网络和其他，收入集合包含其他。
- 初始方案支持自由输入自定义 Emoji，输入非空时覆盖固定选择；切换类型时重置不匹配的固定图标，但保留手动输入值。
- 后端既有 `emoji` 字段和 1 至 16 个 Unicode 字符校验继续使用，不修改数据库 schema 或旧分类。
- **后续演进：** 自定义 Emoji 已在 2026-08-31 迁移为独立共享图标库；下拉选项展示规则则在后续规格中收敛为仅 Emoji。

## 2026-08-30：分类管理交互修订

原文：[分类管理交互修订设计](./2026-08-30-category-management-fixes-design.md)

- 新增分类的图标选择由平铺控件改为下拉框；名称提交前去空白，空名称聚焦输入框并显示“请输入分类名称”，同时把服务端 `label.name_length_invalid` 转为友好文案。
- 删除以服务端结果为准：成功后关闭确认对话框并移除行；拒绝删除时保留对话框，显示可恢复的中文原因，历史引用时提示先停用或迁移。
- “添加分类”按钮保持不换行，并在 1024×768 视口下保证关键控件不裁切。
- **后续演进：** 下拉选项的文字标签已在分类生命周期规格中移除，改为仅展示 Emoji。

## 2026-08-30：分类生命周期与图标下拉

原文：[分类生命周期与图标下拉修订设计](./2026-08-30-category-lifecycle-and-icon-select-design.md)

- 固定图标下拉框只显示 Emoji；当时保留的自定义输入以非空值优先。
- 启用分类只显示停用操作；停用且无历史交易时显示启用与删除；停用且有历史交易时显示启用与迁移并删除。
- 启用调用既有激活 API，成功后分类重新可用于新增记账；服务端拒绝删除时确认框保持打开并提示先停用。
- 验收重点是分类状态对应的操作组合、新交易选项同步，以及失败对话框的可恢复反馈。

## 2026-08-30：总览支出趋势折线图

原文：[总览支出趋势折线图设计](./2026-08-30-overview-expense-trend-design.md)

- 使用总览 API 的每日趋势数据，不能从可能分页的交易列表重新计算。
- 横轴仅显示 `MM-DD`，最多 6 个均匀抽样标签并保留首尾；完整日期点与折线节点始终保留。
- 纵轴按动态最大金额生成 4 个含 `¥0` 的刻度；鼠标悬停或键盘聚焦节点显示“完整日期 · 金额”的 Tooltip。
- 每个点均有可聚焦语义与 `aria-label`；图表保留标题、描述与完整文字摘要。空态、API 失败和其他总览模块维持既有行为。

## 2026-08-30：PocketLog 发布命名统一

原文：[PocketLog 发布命名统一设计](./2026-08-30-pocketlog-release-naming-design.md)

- 面向用户与发行目录统一使用 `PocketLog`，发行包为 `release/PocketLog-<arch>-<os>/`，日志为 `PocketLog-YYYY-MM-DD.jsonl`。
- 可执行文件和 Cargo 包保持技术标识 `pocket-log-backend`；PostgreSQL 相关标识使用小写安全形式 `pocket_log`。
- 修改打包、日志轮转、配置、测试和文档中的当前运行链路命名；废弃设计中的历史 `localStorage` 键示例保留，以避免篡改历史事实。

## 2026-08-30：分类图标紧凑选择与编辑

原文：[分类图标紧凑选择与编辑设计](./2026-08-30-category-icon-editing-design.md)

- 新增分类的固定图标下拉框收窄到约 44 px，仅显示 Emoji，避免占满表单宽度。
- 已有分类增加显式“编辑”按钮；点击后仅展开该行的名称与图标编辑区，支持保存和取消，同一时刻只编辑一行。
- 保存作为单次 `PATCH /api/v1/categories/{id}` 提交，同时携带名称和最终 Emoji；成功响应前不改变全局分类，失败保留草稿。
- 编辑时即使当前 Emoji 不在固定集合，也临时保留该值以防止历史图标丢失。全部控件具备名称、键盘操作和可见焦点。
- **后续演进：** 自由输入自定义 Emoji 已被共享图标库替代，编辑区仅选择下拉框值。

## 2026-08-31：共享自定义图标库

原文：[共享自定义图标库设计](./2026-08-31-custom-icon-library-design.md)

- 自定义 Emoji 从分类新增/编辑表单中拆出，改为分类管理页独立的“自定义图标”区域；新增成功后立即出现在支出和收入共用的图标下拉框中。
- 下拉框合并内置图标与自定义图标，选项仅显示 Emoji；已被分类使用的图标继续展示，本期不提供删除、排序或图片上传。
- 持久化使用 `custom_icons` 表，Emoji 唯一且限制为 1 至 16 个 Unicode 字符。schema 仅由 `migrate` 创建，`serve` 仅校验。
- 新增 `POST /api/v1/custom-icons`，Bootstrap 返回图标库及 `dataRevision`；前端 Provider 成功后使用服务端返回值更新，不乐观污染状态。
- 覆盖校验、重复、revision、事务回滚、API、Provider 和页面交互测试；失败保留输入并提供可恢复反馈。

## 2026-09-01：运行时数据命令

原文：[运行时数据命令设计](./2026-09-01-runtime-data-commands-design.md)

- 将 `migrate`、`demo`、`clean` 与 `serve` 拆分，明确服务启动只校验 schema 和静态资源，不写入账本数据。
- `migrate` 仅创建或升级 schema；`clean` 在事务中清理交易、分类、账户、自定义图标、幂等请求及相关状态，保留表与 `app_state` 行，并重置初始化状态。
- 设计要求 `demo` 只在空账本中写入且不可覆盖用户数据，`clean` 后必须通过显式命令重建演示账本。
- **后续演进：** 当前实现进一步拆分出 `init`；预置分类由 `init` 幂等写入，`demo` 不再创建分类。具体以同日的运行时命令文档同步设计为准。

## 2026-09-01：运行时命令文档同步

原文：[运行时命令文档同步设计](./2026-09-01-runtime-command-documentation-design.md)

- **当前命令模型：** `migrate` 仅变更 schema；`init` 按名称幂等补齐预置分类；`demo` 仅在已初始化的空账本中写入演示账户与交易；`clean` 清空全部业务数据并保留 schema/迁移记录；`serve` 只校验并服务；`package` 只构建发行目录。
- **正确流程：** 首次部署或清空后重建演示账本使用 `migrate → init → demo → serve`；已有 schema 时不重复 `migrate`。`serve` 从不自动迁移或写入数据。
- **预置分类：** 支出为餐饮、交通、购物、居住、娱乐、通讯、网络、水费、电费；收入为工资、其他，共十一项。
- **文档验收：** `AGENTS.md` 与 `README.md` 对六个命令、数据写入边界、预置分类和重建流程保持一致，且不再出现旧的 `clean → demo` 流程。

## 当前维护基线

维护时应优先遵循以下顺序的最新决策：

1. 产品和交互基线：2026-08-18 的 Web UI 规格，以及后续各专项图表和分类管理规格。
2. 后端架构、数据一致性和 API 契约：2026-08-26 的 Rust 后端规格；其运行时初始化部分由 2026-09-01 的命令规格覆盖。
3. 发行布局、同级配置与日志：2026-08-28 的独立发行包规格和 2026-08-30 的 PocketLog 命名规格。
4. 数据命令与部署顺序：2026-09-01 的运行时命令文档同步设计。

原始文档是历史决策的完整记录；当同一主题出现冲突时，以日期更晚且明确标注替代关系的规格为准。
